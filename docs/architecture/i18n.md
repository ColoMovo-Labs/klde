# Locale and voice

Simplified Chinese and English are primary languages. KLDE stores standards-based
`locale=zh_CN` or `locale=en` separately from `voice=standard` or `voice=cute`.
No custom glibc locale is created and the preview does not change the OS locale.
Traditional Chinese, Japanese and Korean are future catalog targets.

The initial data catalogs are UTF-8 JSON resources with stable message IDs.
`I18n.t("shell.launcher.placeholder")` is the presentation entry point. This is
an equivalent resource catalog, not a claim that .ts/.qm extraction exists.
LocaleVoiceModel owns validation, lookup and a revision notification; the QML
wrapper explicitly reads revision so language changes update existing bindings.
English source lookup is a compatibility bridge for existing C++ mock models;
new presentation strings use IDs. External app names use XDG locale metadata,
not translation of arbitrary third-party text.

Fallback: selected locale/voice override -> selected locale Standard -> English
Standard -> visible missing-ID marker. Cute catalogs contain only selected
friendly/shell/ambient overrides. Protected namespaces always use Standard:
security, privacy, legal, destructive, critical, authentication, storage.failure,
certificate and permission. No executable translation packs are loaded.

CI validates JSON syntax and duplicate IDs, required English/Chinese parity,
placeholders, missing IDs, legacy-source coverage, override base presence and
protected namespaces. Tests exercise locale/voice switching, fallback and locked
messages. Cloud captures cover both languages and the Cute prototype. These
checks do not prove all plural forms, RTL, screen readers or 200% layout.

Use QLocale for dates and numeric formatting. Do not concatenate translated
sentences or assume English widths. Search keeps stable app IDs and separate
localized names/keywords/aliases; the mock catalog includes basic Chinese aliases.
A general Pinyin engine is outside this milestone.

Current catalog scope is the implemented preview, not a complete desktop: first
run, real notifications, session authentication, XDG application discovery and
plural/RTL rules are future work. The source-text bridge covers current C++ mock
models; new real adapters should expose message IDs and typed arguments directly.
